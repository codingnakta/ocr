# 테스트

> **원칙:** Mock 테스트가 통과했다고 실제 OCR이 성공한 것은 아닙니다. 또 PDF 파일이 만들어졌다고 뷰어에서 드래그가 된다는 뜻도 아닙니다. 아래 표는 실제로 무엇을 실행해 확인했는지를 구분해 적었습니다.

## 1. 실행 방법

먼저 자산을 받습니다(모델 + 손글씨풍 테스트 폰트).

```bash
cd backend && python scripts/fetch_assets.py
```

Claude Mock 기반 자동 테스트입니다(무료, 약 4분).

```bash
pytest
```

실제 Claude API 테스트입니다(비용 약 $0.20). 실제 사진이 `tests/assets/real/*.jpg`에 있으면 함께 평가합니다.

```bash
RUN_REAL_API=1 pytest tests/test_real_api.py -s
```

브라우저 E2E 테스트는 백엔드(8000)와 프런트엔드(3000)를 실행한 상태에서 돌립니다.

```bash
python tests/make_e2e_fixtures.py ../frontend/e2e/fixtures
```

```bash
cd ../frontend && npx playwright test
```

Claude 비용 없이 E2E를 돌리려면 무료 OCR 모드를 씁니다.

```bash
E2E_OCR_MODE=local npx playwright test
```

### 개발 중 테스트로 발견해 고친 실제 문제

- **똑바른 한글 손글씨 페이지를 180° 뒤집음** → Claude가 뒤집힌 이미지에서 그럴듯한 문장을 지어냄(모두 "불확실" 처리되긴 했음). 줄 방향 분류기가 한글 손글씨에서 무작위에 가깝다는 것을 측정하고, 문서 방향 모델(확률 0.8 이상), Claude의 `page_rotation` 보고, "추측 금지" 프롬프트로 고쳤습니다.
- iPhone MPO 사진이 재인코딩되어 3.1MB가 8.7MB로 커짐 → 기본 JPEG 프레임을 바이트 그대로 추출하도록 수정.
- 주황색 잉크 색조가 30° 바뀜 → 대비 조정을 모든 채널에 같은 선형 변환으로 적용하도록 수정.
- 같은 줄의 이웃 박스가 겹쳐 드래그 시 앞 줄이 잡힘 → 겹친 구간 가운데에서 분할하고 텍스트 높이를 85%로 조정.
- 선택 표시 상자가 드래그 중에 레이아웃을 밀어 선택이 폭주함 → 고정 오버레이로 변경.
- 작업이 끝나면 화면에 "완료"가 표시되지 않음, 맞닿은 텍스트가 한 단어로 합쳐짐, 샌드박스 환경변수(`CLAUDE_EFFORT`)가 설정에 섞임 → 모두 수정.
- 일부 Chromium은 한글 `filename*` 다운로드 이름을 버리고 "download"로 저장함 → ASCII 파일명 사용.

## 3. PDF 뷰어 수동 확인 체크리스트

앱에서 만든 PDF를 각 뷰어에서 열고 확인합니다. 예: `test.jpg`로 만든 PDF.

| 확인 | Chrome 내장 | Edge | Acrobat Reader | macOS 미리보기 | iOS/Android |
|---|---|---|---|---|---|
| 원본 사진이 그대로 보임(글자 겹침 없음) | ☐ | ☐ | ☐ | ☐ | ☐ |
| 손글씨 한 줄을 드래그하면 그 줄이 선택됨 | ☐ | ☐ | ☐ | ☐ | ☐ |
| 복사·붙여넣기 시 한글이 깨지지 않음 | ☐ | ☐ | ☐ | ☐ | ☐ |
| 여러 줄을 복사하면 순서가 맞음 | ☐ | ☐ | ☐ | ☐ | ☐ |
| Ctrl+F "순차회로" 검색 시 해당 위치가 강조됨 | ☐ | ☐ | ☐ | ☐ | ☐ |
| 회전된(가로로 찍은) 사진 페이지도 똑바로 보임 | ☐ | ☐ | ☐ | ☐ | ☐ |

참고: 텍스트는 줄 단위로 상자 길이에 맞춰 늘리거나 줄여 배치합니다. 그래서 한 줄 **안의** 글자 위치는 손글씨와 조금씩 어긋날 수 있습니다(글자 단위 좌표는 쓰지 않음).

## 4. 정확도 평가 도구

- **화면:** `/evaluate`에서 이미지 1장과 정답 텍스트(선택)를 넣으면 로컬·AI·하이브리드를 나란히 비교합니다. CER, WER, PDF 텍스트 CER, 누락 의심 줄, 시간, 비용을 보여줍니다.
- **CLI:** 같은 폴더의 `이름.gt.txt`를 정답으로 씁니다. 정답이 없는 이미지는 정확도를 계산하지 않습니다.

  ```bash
  python -m app.evaluation.cli <폴더> --engines local,ai,hybrid --out report.json
  ```

- **정답 작성 규칙:** 사람이 확인한 텍스트를 한 줄에 한 줄씩 적습니다. 잘린 글자는 보이는 만큼만 적습니다. CER은 기본적으로 공백을 무시합니다(`cer_with_spaces`도 함께 제공).

## 5. 정확도에 대한 주의

- 합성 이미지는 손글씨 **폰트**로 만든 것이라 실제 손글씨보다 훨씬 쉽습니다. 실제 정확도는 직접 필기한 사진과 정답으로 측정하세요. 사진 10~20장과 정답만 있으면 위 CLI로 바로 측정할 수 있습니다.
- Claude 결과는 실행마다 조금씩 다를 수 있고, 잘리거나 흐린 글자는 틀릴 수 있습니다. 그래서 불확실 표시, 재인식 비교, 원본 OCR 보존, 검수 화면을 둡니다.

## 6. Docker 검증 메모

- `docker compose up -d --build`와 같은 구성(PostgreSQL 16, backend, worker, frontend)을 실제로 띄워 확인했습니다.
- 개발 샌드박스에서는 Debian apt 미러와 일부 레지스트리가 막혀 있어, 베이스 이미지는 `PYTHON_IMAGE`/`NODE_IMAGE` 빌드 인자로 미러를 지정해 빌드했습니다. 일반 환경에서는 기본값(Docker Hub) 그대로 쓰면 됩니다.
- 백엔드 이미지는 apt 패키지 없이 동작합니다(onnxruntime·opencv-headless 휠 자체 포함, 빌드 중 import 검사).
